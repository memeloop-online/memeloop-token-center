# 请求用量与本地结算口径

请求列表、详情、SSE 事件和账户结算流水新增可空 `usage_basis`。该字段与终态、用量和结算流水在同一个数据库事务中落地，不增加逐行查询。

| 值 | token 含义 |
| --- | --- |
| `provider_reported` | 从有效供应商用量报告取得；不是供应商发票证明 |
| `provider_estimated` | 供应商组件明确标为估算的用量 |
| `contract_ceiling` | 历史记录曾把合同保守上限写入本地结算；不是实际生成量或供应商账单证明 |
| `not_observed` | 未取得可计入该请求的有效用量 |
| `null` / 缺省 | 历史或非文本记录，来源未知；不得根据状态码推定 |

只有 `provider_reported` 的输出 token 可以作为实测 TPS 的分子。上限、估算和未知记录不得标为实测生成速度；没有可靠生成时长时，生成 TPS 仍未知。

`cost` / `billing.cost`、账户结算流水、今天费用与用量分析费用表示本地记录的结算金额，不是供应商发票金额。历史 `contract_ceiling` 行可能包含保守上限结算，调查和更正时必须单独圈定，不能把它称为已证实的实际成本。

已交付输出后，如果捕获到完整且有效的供应商终态用量，之后下游断连或发送超时仍保留这份用量用于结算；错误状态保留，不伪装为 200。若未取得完整有效用量，请求以 `not_observed` 和零本地实际用量结算，原始 reservation 上限仍留在 `usage_reservations` 审计记录中，但不再提升为 actual cost。零本地结算不证明供应商免费：外部账单可能仍产生费用，需要用供应商证据另行对账。

此时 `usage_reservations.status` 进入 `settled`、`actual_micros=0`，账户与限额中的 reserved 占用在同一事务释放；行内保留的 `reserved_micros` / `reserved_tokens` 只是入场估计快照，不表示仍冻结。单请求界面必须显示“费用未知”，而不是把数值零称为实际费用零。汇总和趋势只称“本地结算”，并明确未覆盖供应商未知费用。缺口数量的唯一口径是所选范围内已终态、`usage_basis=not_observed` 的文本请求数；不得用 HTTP 499 总数替代，因为 499 仍可能携带有效 `provider_reported` 用量。

迁移 93 仅新增可空来源字段。历史记录没有补填、退款或重算；历史影响调查必须区分已结算账本金额和能够证明的供应商实际用量。重放同一终态不能改变已提交的来源或重复结算。
