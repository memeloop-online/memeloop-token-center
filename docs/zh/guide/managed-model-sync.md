# 托管模型同步 API

`POST /internal/v1/upstreams/{account_id}/models/sync-routes` 显式选择将账号发现的模型用于创建托管路由。调用需要同时具备 **`providers:write` 和 `routes:write`**，租户边界与账号管理相同。已有的 `models/sync` 接口和后台刷新仍只执行原有的目录刷新行为。

响应包含 `catalog`、`routes`（`added`、`disabled`、`restored`、`unchanged`、`skipped`、`warnings`）和 `price_sync`。HTTP 200 也可能表示安全跳过，应检查警告；`sync_in_progress` 表示另一目录请求持有租约，调用方可重试。

完整的非空目录发布并完成托管路由协调后，同一请求会为目录中去重的模型标识同步美元价格，使用配置的 `models.dev`、LiteLLM 和 OpenRouter 目录及既有确定性匹配器。模型集合不来自历史请求，调用方也不能通过该接口提交模型名、来源 URL、币种或价格。

价格同步只针对已验证目录，不能借此任意修改全局价格。调用该接口仍只需上述两个权限；直接管理价格仍需全局 `prices:write`。手工价格不会被覆盖。优先来源不可用时保留该来源的最后已知价格，不降级采用较低优先级来源。未匹配或存在歧义的模型会被报告且不写入；来源或定价失败不会回滚目录和路由变更，也不会写入虚构的零价格。

只有完整、成功且非空的目录响应才允许协调路由。部分或分页响应、格式错误的记录、认证失败、超时和空目录均保留原有目录与托管路由；不会跟随分页 URL。如果发布目录后、协调路由前目录或账号发生变化，路由变更会被跳过，重试可使状态收敛。

原生 Codex 的仅刷新同步也要求完整目录，包括每小时后台刷新。部分 HTTP 响应或分页、不完整标记会记录过期或错误结果并释放同步租约，不替换原快照、改变模型可用性或启动价格同步；已有重试计划不变。新发现的模型仍需显式创建路由并授权，后台发现不会授予访问权限。

当前组件插件的 `list-models` ABI 返回普通数组，没有完整性或续页契约。因此该接口会以 `complete_catalog_unsupported` 拒绝组件插件负责的发现；已有的仅刷新 API 仍可使用。原生和 HTTP 发现使用各自明确的传输与响应校验路径。

每条托管路由有稳定的租户、账号、上游模型和协议所有权键。初始公开模型名与上游模型名相同，优先级为零。目录中的 `any` 协议只映射为 `openai`；明确列出的受支持协议保持不变。不支持的协议和超出路由限制的模型名会被跳过并产生警告。现有手工候选（包括公开模型名相同者）保持独立，不会被接管。

同步不会创建或替换凭据授权或分组，新路由仍需正常的显式授权流程。同步只控制其自身未被修改的路由的启用状态：模型消失时以 `catalog_missing` 禁用，再次出现时只恢复这一禁用原因。操作员变更状态（包括禁用已经自动禁用的路由）会永久阻止自动恢复；修改路由字段或关联也会将控制权交还操作员。已归档或删除的路由不会重建；删除会留下托管键墓碑。此版本没有自动接管或重置接口。
