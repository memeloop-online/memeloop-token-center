# 自定义 Codex 模型的预留上限

选择或保存自定义模型不等于确认其财务上限。缺少该模型的预留配置时，路由仍可保存；网关跳过该候选，在任何预留、归档入库或上游发送之前停止。其他已授权、具备自身有效配置的候选可正常使用，不会相互复制额度。

补配置的最短路径：

1. 同步该账户模型目录，优先使用认证目录中**精确同名模型**的上限。当前 Codex 目录仅公布上下文窗口时，其来源是 `mtc_context_window_bound`：这是保守预留界限，不是供应商宣称的输出最大值。
2. 目录缺失或同步失败时，核实供应商的精确同模型输出限制或已有明确管理配置来源，然后通过现有上游配置表单填写 `reservation_token_bounds`。不要把其他模型的上下文、其他账户的历史未知数值或解析器整数最大值当作依据。无需新增审批流程。
3. 先只读检查保存后的账户/精确模型配置和价格；确认潜在预留金额后，再按原有授权执行正常功能验证。

旧版本在自定义模型缺值时自动写入 `1000000000`。此修复停止生成该值，但不按数值扫描删除历史配置：相同数字可能是合法显式配置。仅对有前后配置快照、操作审计或其他来源证据的具体账户/模型，使用现有路由禁用或配置 CAS 进行定点隔离；来源不明时保留不确定，不自动改写。禁止自动退款或重算历史账本。

预留金额只是请求执行前冻结的财务暴露，不等于已结算费用。若收到完整有效供应商用量，按实际报告结算；已交付计费输出但缺少可靠用量时，现有合同策略可能以保守上限结算。因此上限必须有依据，不能用猜测的小默认值替换巨大默认值。
