# 广电（CBCNX）上游

广电（CBCNX）使用内置 `cbcnx` 提供商类型。它是一个受限的
OpenAI-compatible HTTP 接入：不需要专用转发进程，不把凭据写入路由、
日志或 Git，也不因模型名称而自动创建、授权或公开模型。

## 已实现的边界

- 文本、Chat、Responses-compatible 请求和嵌入走已有的有界 HTTP 传输、
  请求归档、路由健康、并发/速率限制和价格结算路径。
- 标准 OpenAI Images 路由可使用 CBCNX 图片模型。URL 结果只能来自同源或
  `result_origins` 中明确配置的精确 origin；随后由服务流式归档。Base64
  结果同样受同步图片响应和并发缓冲边界约束。
- 账户配置必须固定 `stream_usage_contract` 为
  `openai-chat-usage-only`。当调用方请求 Chat stream usage 时，终端 usage
  必须符合已验证的 OpenAI 形状；无 usage、负数、溢出或不一致 usage 不会
  被当作零成本成功。
- `input_token_overhead_ceiling` 仅可由管理员配置为有界、可信的预留补偿。
  对于缺少可结算 usage 的成功响应，核心仍使用已预留的上界，不会放弃计费。

管理端创建 CBCNX 上游时，选择“广电（CBCNX）”，填写由管理员确认的 API
地址和 API key。凭据字段只会进入加密的上游凭据 envelope；它不得出现在
配置、路由、导出的清单、测试 fixture 或支持工单文本中。

## 模型和价格准入

模型发现只是编辑路由时的候选目录。一个模型只有同时满足前两项才会被
客户端发现；调用还必须满足第三项：

1. 管理员创建了精确的模型路由并把它授予客户端凭据；
2. 该路由协议与 CBCNX 已声明能力相符；以及
3. 该模型在客户端币种有有效的 Token 或生成价格。

缺少价格时，核心在任何上游 HTTP 调用之前返回
`unpriced_model`（HTTP 424）。这不依赖余额或预算是否配置，因此新模型不
会以零价格开放。价格同步只补充明确匹配；没有可靠同步结果时应由管理员
设置人工价格，再开放路由。

当前已声明能力为 `text`、`embedding`、`image`。图片模型需要标准
OpenAI Images 输出和有效的 `image` 或 `job` 单价。管理员应保留每个模型
的上游文档版本、模型 ID、价格来源和验收记录；模型别名不是价格或能力
证据。

## 视频候选模型

广电目录中可能出现视频或音视频模型，但目前 `cbcnx` **不声明 video
能力**，也不接受这些模型进入 `/v1/videos/generations`。这样即使有人创建
了同名路由，调用也会在请求、额度预留和上游提交之前失败关闭。

要开放一个视频模型，必须先单独增加并验证固定的提交、轮询、取消、结果
origin、流式对象归档和按秒/任务结算契约。验收先使用受控小样本和 CI mock，
检查 worker/gateway 内存、对象大小、幂等重放和失败退款；真实外部视频请求
需要发布负责人另行批准，不能由普通模型同步或压力测试触发。

## 验收清单

文本和图片发布验收应保留以下不含密钥的证据：

- `/v1/models` 只包含被授予且当前可选的模型，未定价模型的调用会在出站前
  被拒绝；
- 一个非流式和一个 SSE 文本请求都有正的、受上界约束的结算；
- 一个图片请求的归档、私有下载 `Content-Length`、相同幂等键重放和统计都
  准确且只发生一次；
- 并发小批量文本请求不突破每凭据并发、预算或路由健康边界；以及
- 未定价文本、图片和视频候选模型均在出站前被拒绝。

视频压力与大资产验收是后续工作，不是文本/图片发布完成的替代证据。
